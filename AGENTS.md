# Fermia (formerly KouKou Ferme) — AGENTS

Offline-first farm SaaS (poultry first, multi-species, crops) for Gabon, now served as a **POUFA-only instance** (government poultry programme): every farm is a programme farm created by the registry, see « Programme (POUFA) ». Brand renamed KouKou → **Fermia**: user-visible text only — storage keys (`koukou.*`), DB name `koukou_ferme` and Expo slug `koukou-mobile` are intentionally unchanged (renaming storage keys would drop unsynced offline cash ops and log users out). Repo: https://github.com/MOCTAR10/koukou

## Repo shape

`backend/` (NestJS), `web/` (farm owners + platform admin), `mobile/` (Expo), `docs/`.

**No root `package.json`, no workspaces, no root lockfile.** Three independent npm projects — every command runs from its own directory. There is **no root README**: `backend/README.md` and `mobile/README.md` are upstream boilerplate (Nest / create-expo-app) — ignore them, this file is the real map.

CI (`.github/workflows/ci.yml`): push to `main`/`feat/**` and PRs to `main`. backend = build+lint+test, web = build+lint, mobile = typecheck+lint+test+`expo export` Android bundle (catches missing assets/Metro errors tsc cannot see). **E2E** (`.github/workflows/e2e.yml`): PRs to `main`, pushes to `main`, nightly 02:00 UTC and manual; PostGIS service container with the default `postgres/postgres` credentials. `concurrency` cancels superseded runs. Node pinned to 22 (Expo quirk) — change all four places together (the three `ci.yml` jobs + `e2e.yml`).

- Single test: `npm run test -- <filter>` in `backend/` or `mobile/` (vitest). Backend e2e: `npm run test:e2e -- <filter>`.
- Prettier: `npm run format` exists in **backend and web only** — mobile has no `format` script (and no `.prettierrc` anywhere except `backend/`). Format is separate from lint.
- `web`: `npm run types` regenerates `src/api/schema.d.ts` from a **running** backend. Output is **not imported** — `src/api/types.ts` is hand-maintained and authoritative. Never edit `schema.d.ts` to fix a type error.
- `mobile`: use `npm run lint`, **not** `npx expo lint` (Node 22 issue).
- Green baseline (verified): backend unit 26 files/308 tests, mobile 24 files/391 tests. Backend e2e: re-verify on a fresh DB once the POUFA-only spec migration is merged (last full run before it: 45 files/548 tests).
- **Full backend e2e is expensive**: 45 specs, forced sequential (`fileParallelism:false`, `maxWorkers:1`), each boots the whole AppModule (pending migrations run, then the seed) against the same DB. ~4 min locally, ~2 min on CI. Filter by name while iterating.
- **`vite-tsconfig-paths` is deliberately not installed.** It was a no-op (backend tsconfigs declare no `compilerOptions.paths`, no source file uses alias imports) while pulling in the deprecated `tsconfck`, whose optional peer `typescript@^5.0.0` conflicts with TypeScript 6 — newer npm resolves that peer to 5.x and aborts `npm ci` with `Missing: typescript@5.9.3 from lock file`, which **only reproduces on CI**, never on npm 10.x. Do not re-add it. (`mobile` defines its own `@`→`src` alias inside `vitest.config.mts`.)

## Windows / encoding (this repo is edited on Windows)

- **Never `Get-Content`/`Set-Content`/`Out-File` French UTF-8 files in PS 5.1.** `Get-Content` reads as ANSI and renders `é`→`Ǹ`; `Set-Content` adds a BOM *and* corrupts. Use the `read`/`write`/`edit` tools, or `[System.IO.File]::WriteAllText($p,$s,(New-Object System.Text.UTF8Encoding($false)))`. Tracked files are clean UTF-8 — any `Ǹ`/`â€¦` in console output is a *display* artifact, not damage. Verify before "fixing".
- `.gitattributes` pins `*.ts` and `*.md` to `eol=lf`. Working tree is CRLF on Windows and git warns on every write. Keep LF in the file.

## Backend gotchas

- **Relative imports MUST end in `.js`** (tsconfig `module`/`moduleResolution: nodenext`, `type: module`). All ~1385 relative imports in `src/` + `test/` comply — including tests. A missing `.js` is a runtime `ERR_MODULE_NOT_FOUND`, not a type error.
- **Property-level `@Index('name', ['a','b'])` silently corrupts.** Verified in `node_modules/typeorm/decorator/Index.js`: `columns: propertyName ? [propertyName] : fields` — the field list is **discarded**, while the composite `name` and `unique: true` survive. Result: a single-column unique index under a misleading name. Multi-column `@Index` must be **class-level** (above `@Entity`); single-column may be property-level.
- **Entity circular imports + `emitDecoratorMetadata`** can cause TDZ crashes. Break cycles with `import type` and relation-by-**name** (`@ManyToOne('JournalEntry')`) — never mutual value imports.
- **The schema is owned by migrations** (`src/database/migrations/`, table `schema_migrations`), run at boot (`DB_MIGRATIONS_RUN`, default true). `DB_SYNCHRONIZE` now defaults to `'false'` — a local escape hatch only. Options live in `src/database/typeorm-options.ts`, shared by `app.module.ts` and the CLI data source `src/database/data-source.ts`. **Every entity change needs a migration**: `npm run build`, then `npm run migration:generate -- src/database/migrations/<Name>` against a DB at the latest migration, review the SQL, **register the class in `src/database/migrations/index.ts`** (an explicit list, not a glob, so vitest e2e runs them from the TS sources), rebuild. `npm run migration:check` fails on drift (CI e2e runs it). The `Baseline` migration *adopts* a database `synchronize` already built (it returns early when `farms` exists). Seeding is idempotent from `onApplicationBootstrap` in `src/database/database-seed.service.ts` (~2780 lines). Enums live in `src/common/enums/` (40 files) — don't inline string unions.
- **Bands are never deleted**: `production_batches.farm_id` is `ON DELETE RESTRICT` (POUFA spec); there is no farm or band delete route.
- **`.env` is gitignored; `backend/.env.example` is the tracked template** (every variable below, plus `TASK_SWEEP_DISABLED`, `MARKET_SWEEP_DISABLED`, `AUDIT_SEAL_DISABLED`, `PUSH_DISABLED`, `EXPO_ACCESS_TOKEN`) — keep it in sync when adding a variable. Every `DB_*`, `PORT`, `SWAGGER_PATH`, `JWT_EXPIRES_IN` has an inline default. **`PROGRAM_CODE` is mandatory** (`POUFA`): `ProgrammeService` and `ScopeResolver` stop the boot without it (`programme/program-code.ts`, French message); the migration CLI does not need it. The other one that matters: **`JWT_SECRET`** — `auth/auth.secret.ts` falls back to a random 48-byte secret, generated once per process (signer and verifier share it; and treats `''` / `koukou_ferme_change_me_in_production` as placeholders), which **silently invalidates all sessions on every restart**. Optional `PLATFORM_ADMIN_EMAIL/PHONE/PASSWORD` (+`PLATFORM_ADMIN_NAME`, default "Administrateur Plateforme") seed the platform admin; absent → warning, no admin created. `UPLOADS_DIR` overrides the farm-logo upload dir (default `backend/uploads`, gitignored); logos are capped at 2 MiB and must carry a PNG/JPEG/WEBP signature.
- **CSV exports** go through `CsvService`, which prefixes `'` to text cells starting with `= + - @` (formula injection) — numbers stay as is.
- **Rate limiting is off in e2e only**: `test/e2e-setup.ts` sets `THROTTLE_DISABLED=true`, read by `ThrottlerModule.skipIf` in `app.module.ts` (auth allows 5 logins/min per IP, the suite does hundreds). Never set it in a deployed environment.
- **e2e needs a live local PostgreSQL** on `DB_HOST:DB_PORT` reading the same `.env`. Each spec boots the full app, which applies pending migrations. Use unique IDs/timestamps and `*.e2e.ga` emails. `test/e2e-setup.ts` sets `PROGRAM_CODE=POUFA` (never set it per spec). **Build accounts and farms with `test/helpers/programme-farm.ts`**: `createPlatformAdmin` (buyer promoted by SQL), `createProgrammeFarm` (registry farm + `activate-owner` + owner token), `addProgrammeFarm` (another farm of the same owner, `linkExistingUser`), `registerBuyer`, `uniquePhone`, `login`, `auth`. The suite never deletes nor detaches a farm (`program_id` is NOT NULL; `session_replication_role = replica` disables triggers, not constraints), so specs must stay correct when re-run on the same DB: scope every assertion to the spec's own farms (never count all farms or expect a given code such as `G1-0001`), and match codes as `/^G1-\d{4,}$/` (they widen past 9999). Names posted to `/programme/farms` **without** `confirmDuplicate` must be unlike earlier runs': the duplicate detector compares character bigrams, so `Ferme ${Date.now()}` vs the previous run's is a probable duplicate (409) — append random letters instead (see `programme-farms.e2e-spec.ts`). `globalThis.fetch` is mocked in `test/e2e-setup.ts` (weather returns THI<75 comfort forecast to keep every other spec deterministic and offline); only `weather.e2e-spec.ts` overrides and restores it. Unmatched URLs resolve to a 404 stub.
- **Phones** are normalized (`common/utils/phone.ts`: spaces, dots, dashes, brackets removed) at buyer registration, employee creation, registry sheets and owner activation; login also tries the raw value for older accounts. A concurrent duplicate registration answers 409.
- **Auth**: only buyers sign up (`POST /auth/register-buyer`). There is no owner sign-up, no `become-farmer` and no `POST /farms` / `POST /admin/farms` (all 404): an exploitant's account comes from `POST /programme/farms/:farmId/activate-owner`, agents and institutions from access memberships, the platform admin from the seed. `@Public()` exists on `auth.controller.ts` (`/auth/register-buyer`, `/auth/login`, `/auth/login/otp`) and the read-only Market catalogue (`GET /market/listings[/:id]`), which goes through a whitelisted DTO: no batch id, cost, GPS or phone. Everything else is JwtAuthGuard → ProgramAccessGuard → RolesGuard → PermissionsGuard. Phone + code secret, 7d token. Swagger at `/api-docs` (3000), off when `NODE_ENV=production` unless `SWAGGER_ENABLED=true`. `TRUST_PROXY` = number of reverse proxies (default 0): required behind a proxy or all clients share one login rate limit.
- **DB naming**: snake_case columns, camelCase TS. **Error messages and all user-facing text are French.**
- **PDFs** (pdfmake 0.3.11): register fonts via `virtualfs.writeFileSync` + `addFonts(...)`; `createPdf(dd).getBuffer()` returns a **Promise**. Set `setUrlAccessPolicy`/`setLocalAccessPolicy(() => false)` to silence warnings. VFS types at `src/common/types/pdfmake-vfs.d.ts`. Use the shared `PdfService` (`src/common/services/pdf.service.ts`, exported by `CommonModule`) — never build a second pdfmake instance per feature.

## Language, roles & permissions

- **UI text, labels, errors: FRENCH. Code identifiers and comments: English.** French comments exist but new code should be English — don't "normalize" the codebase either way.
- `UserRole`: `PLATFORM_ADMIN` (inherits PROPRIETAIRE), `PROPRIETAIRE` (full), `ELEVEUR` (member), `ACHETEUR` (Market buyer, no farm data: only `GET /farms`, which answers empty, and the `/auth` buyer routes; a buyer never becomes an owner by himself, and `activate-owner` refuses to link a farm to a buyer account). `INSTITUTION` (programme institutions, see « Institutional access ») and `OPERATEUR` (reserved, refused everywhere). Any new route needs `@Roles`, or a buyer reaches it — **and every controller needs a class-level `@Domain(...)`** (`controller-domains.spec.ts` fails otherwise).
- `FarmStaffRole` is **per farm link**, distinct from `UserRole`: `ADMIN` (flexible, per-link permission list) vs `ELEVEUR` (fixed).
- Effective permissions resolve in `farms.service.ts` (`assertAccessible`/`profileOf`): owner and PLATFORM_ADMIN get `ALL`/`['*']`; `ADMIN` gets **exactly the stored `link.permissions` filtered by `isPermissionCode` — there is no default set, so an empty list means no permissions**; `ELEVEUR` always gets `ELEVEUR_DEFAULT_PERMISSIONS`. A `permissions` payload is refused for ELEVEUR.
- Suspended farm → sales blocked (400). Suspended user → login 401.
- `sanitaire:signaler` (default for ELEVEUR and new ADMIN): create a health event or a single vaccine schedule; generate/edit/delete stay `sanitaire:gerer`.
- **Authz is two layers**: broad `@Roles(...)` plus fine-grained `@Permissions('code', ...)`; owner/PLATFORM_ADMIN bypass both. The catalog is the single source of truth: `src/common/permissions/permission-catalog.ts` (`PERMISSION_CATALOG` = every group, `PermissionCode` derives from it; `PERMISSION_GROUPS` = what is served). **Never invent a permission code** — gate new routes with existing ones or add to the catalog.
- **« Évolution » groups** (`EVOLUTION_PERMISSION_GROUPS`, today `agriculture` = `agri:gerer`, the Cultures module hidden in the apps): left out of `PERMISSION_GROUPS`/`PERMISSIONS`/`isPermissionCode`, so `GET /farms/:farmId/permissions` does not offer them, a member payload naming one is a 400 « Permission(s) inconnue(s) », and a code already stored on a link stays in the DB (kept when the list is replaced, `withDormantPermissions`) but grants nothing and is never returned (`/me`, member list/edit) nor counted in delegation checks. The dormant `agri:gerer` routes (parcelle/récolte writes) are therefore owner/PLATFORM_ADMIN only; reads stay open to members. Remove the key to turn the group back on. Mobile gates with `useFarmProfile().hasPermission()`; per-code constants are mirrored in `mobile/src/constants/permissions.ts`.

## Key invariants

### Programme (POUFA)
- **`PROGRAM_CODE` is mandatory** (`POUFA`, one programme per instance; the app refuses to start without it). `ProgrammeService.current()` always returns the programme (an `Error` if its row is missing, which the boot seed prevents). `ProgrammeSeedService.onApplicationBootstrap` seeds (one transaction, advisory lock, `ON CONFLICT DO NOTHING`) the `Program` row, Gabon's 9 provinces + 49 localités (`programme/data/gabon-provinces.ts`, spelling caveats inside), the default lists and the catalog defaults; it never overwrites a row and never adds a parameter version once a key has one. Province boundaries are **not** seeded (licence): an admin uploads them (`PUT /programme/provinces/:code/geometry`). The seed does not live in `database-seed.service.ts`.
- **Parameters are versioned and immutable** (`program_parameters`, a DB trigger refuses UPDATE/DELETE): `POST /programme/parameters/:key` inserts a new row with `validFrom` (now or future, never past) and a mandatory reason. The value in force at D = latest `validFrom` ≤ D, ties by latest `createdAt` (`parameter-resolution.ts`). Read them with `ParametersService.get(key, at)` at the **date of the fact**. Keys are a typed catalog (`programme/parameter-catalog.ts`: type, unit, min/max, owner profile, « Proposé » default); unknown key → 400. A `FORMULE_<KEY>` value is accepted only if the whole indicator set still compiles (`compileIndicatorSet`) at its date and at every later scheduled formula change. `ownerProfile` is enforced in `ParametersService.set`: only that institutional profile (DGE, VETERINAIRE, ADMIN) or PLATFORM_ADMIN changes a parameter.
- **Lists** (`RefItem`, `ProgramListType` enum): items are deactivated, never deleted; `code` and `family` never change. Code reacts only to `family` (`ref-list-families.ts`: STATUT_FERME, INTRANT, MOTIF_SORTIE, TYPE_OPERATEUR, STATUT_ALERTE require one), never to a code or label. Reads `?all=true` (inactive included) are admin-only.
- **`IdCounterService.next(scope, em?)`**: one atomic upsert (`ON CONFLICT … next + 1 RETURNING`), usable inside the caller's transaction (the counter row stays locked until commit; a rollback gives the number back since it was never stored). `id_counters.next` holds the last number handed out. Farm codes `farmCode('G1', 12)` = `G1-0012` (scope `FARM:G1`); localité codes `G1-06` continue after the seeded ones.
- **GPS ↔ province** (`GeoService.checkPoint`, `common/geo/point-in-polygon.ts`, ray casting, holes and MultiPolygon, boundary = inside) is a **warning, never a block**: `inside` is null when the province has no boundary loaded.
- **Programme farms** (`programme/farms/`, `/programme/farms/*`, PLATFORM_ADMIN or an institutional profile with REGISTRE, within its scope; the farm's owner may `GET` his own sheet) are **every** `Farm` row (`farms.program_id` NOT NULL since `FarmsAlwaysProgramme`, which refuses to run on a database holding farms outside the programme, i.e. former Fermia demo data) plus the registry sheet (code, province/localité, `amiRef`, cohort, `capacityPlaces`, exploitant name/phone, GPS metadata, `statusCode`). `code` (`G1-0012`, `IdCounter` scope `FARM:<province>`) and `programId` never change once set (DB trigger `farms_programme_code_immutable`); the registry is open-ended (`POST /programme/farms` one by one, or import). A POUFA instance starts from an empty database: there is no enrolment of an existing Fermia farm.
- **`Farm.ownerId` is nullable** (an exploitant may have no account yet). Never assume `farm.owner`/`farm.ownerId` is set: guard comparisons, owner notifications (`push.service.ts`), the Market contact phone (falls back to `exploitantPhone`). `POST …/:farmId/activate-owner` creates the PROPRIETAIRE from the sheet's phone (login code returned once; SMS later) or, with `linkExistingUser: true`, attaches the farm to the existing PROPRIETAIRE of that phone (one exploitant, several farms). The account's role is checked **before** `linkExistingUser`: a Market buyer's phone → 409 `{ buyerAccount: true }` (`BUYER_PHONE_MESSAGE`: another number is needed on the sheet), any other non-PROPRIETAIRE account → 409; only a PROPRIETAIRE without the flag gets `{ existingAccount: true }`.
- **`GET /farms`** (every role's farm list) adds `provinceCode` / `provinceName` (null without a province) to each farm, read in one query for the whole list (`FarmsService.withProvince`).
- **GPS point, buildings and capacity = registry only** too: `PATCH /admin/farms/:id` answers 400 to `latitude`/`longitude` (`FARM_GPS_IN_REGISTRY`: use `PUT /programme/farms/:farmId/gps`, history + province check) and to `buildingCount`/`capacityPerBuilding`/`buildingAreaM2` (`FARM_CAPACITY_IN_REGISTRY`: `capacityPlaces` and infrastructures), before writing anything. The admin route keeps `administrativeCity`, `defaultSacKg` and `isVerified`.
- **Farm name = registry only**: `PATCH /farms/:farmId` and `PATCH /admin/farms/:id` answer 400 (`FARM_NAME_IN_REGISTRY`) to any `name`, whatever its value, before writing anything; only `PATCH /programme/farms/:farmId` renames, with the duplicate check. `administrativeCity` stays editable there (weather geocoding). Specs rename through the registry (`confirmDuplicate: true` when earlier runs left resembling names).
- **Status**: `farm_status_history` (current = latest `from`; `Farm.statusCode`/`statusSince` are a copy written in the same transaction). `Farm.active` follows the family (SUSPENDUE → false), so the existing "suspended farm" rules apply; `PATCH /admin/farms/:id {active}` is always refused (400). GPS fixes go to `farm_gps_history` (a correction never erases the previous point). Infrastructures: `farm_infrastructures` (INFRASTRUCTURE list code, count, surface). Occupation = open bands' chicks placed with the `FORMULE_TAUX_OCCUPATION` in force.
- **Duplicates** (`farms/registry-rules.ts` `duplicateScore`, pure; CDC §5 « blocage des doublons »): `amiRef` unique per programme (409, no override). Otherwise every programme farm is scored, threshold 0.85: same province + normalized name (accents, punctuation and generic words like ferme/coopérative/agricole/avicole/élevage/société/ets removed) equal = 1 or Dice ≥ 0.85 = its similarity, enough alone; a name that only resembles (Dice ≥ 0.6, any province) 0.4; plus corroborating signals GPS < 200 m 0.5, same exploitant phone 0.4, same exploitant name 0.3, same localité 0.1 (`DUPLICATE_WEIGHTS`). No signal alone blocks: the phone or the exploitant alone is one exploitant with several farms. A probable duplicate answers 409 with `duplicates` (visible candidate: `farmId`, `code`, `name`, `provinceCode`, `provinceName`, `score`, `reasons`; the import report's `duplicates` have the same shape plus `line` for an earlier line of the file) unless `confirmDuplicate: true`, stored in `Farm.duplicateOverride`. **Cloisonnement**: for an institutional caller, candidates out of its scope come as `{ hidden: true, score, reasons }` (no code, name or id) and it cannot confirm against them (409 even with `confirmDuplicate`; a national admin decides); `sheetFor(viewer)` filters `duplicateOverride.candidateCodes` to the viewer's scope (none for the owner). Registry writes take an advisory lock per programme.
- **Import** `POST /programme/farms/import` (multipart `file` CSV `,`/`;`, UTF-8 or Latin-1, or JSON `rows`; **`dryRun` defaults to true**; one transaction for a real run): POUFA list `numero,nom,province` (`numero` = alphabetical order, ignored) or the full format (headers matched tolerantly). Idempotent: same `amiRef`, else same normalized name (spaces ignored) in the same province → « déjà présente »; fuzzy duplicates are rejected unless `confirmDuplicate`. Report per line with a French reason. e2e fixture: `test/fixtures/fermes-poufa.csv` (150 farms).

### Institutional access (`modules/access`, POUFA plan §5)
- **`UserRole.INSTITUTION`**: what the account may do lives in its single `ProgramMembership` (profile + `provinceIds`/`farmIds`, `active`, `validUntil`) on an `AccessProfile` (`scopeKind` ALL|PROVINCES|FARMS|FINANCED|OPERATOR|AGGREGATE|AUDIT, `matrix` domain → actions, `system`). The 7 system profiles (`access/data/default-profiles.ts`: AGENT_TECHNIQUE, DGE, VETERINAIRE, BCEG, MAEDR, ANINF, ADMIN — codes = parameter owner profiles) are seeded by `ProgrammeSeedService`; tunable, never deleted, scope kind fixed. Admin: `/programme/access/{catalog,profiles,memberships}` (PLATFORM_ADMIN or ADMINISTRATION:ADMINISTRER; no self-edit), `GET /programme/access/me` (domain SESSION).
- **`PATCH /programme/access/memberships/:id`** also edits the account: `fullName`, `phone` (normalized by `normalizePhone`; it is the login — another account's phone is 409, a Market buyer's 409 with `buyerAccount: true`) and `email` (optional, unique, `null` clears it; another account's is 409). Still no self-edit.
- **No escalation by an institutional admin** (`access-rules.ts` `scopeKindRefusal` / `matrixExcess` / `scopeExcess`, enforced in `AccessAdminService`; PLATFORM_ADMIN is not limited): creating or patching a membership, it grants only (1) a scope kind within its own — ALL grants any kind, PROVINCES grants PROVINCES or FARMS, FARMS grants FARMS, any other kind grants nothing; FINANCED/OPERATOR/AGGREGATE/AUDIT only from an ALL scope —, (2) a profile whose matrix is a subset of its own (so the AUDIT profile ANINF, whose domain no other profile may hold, is granted by the platform admin only), (3) provinces among its own and farms within its scope. It also manages only accounts it could have granted (a PATCH on a broader account — even `{active: false}` — is 403 `plus larges que les vôtres`). Same rules for profiles: create / patch / delete only a profile within its own kind and matrix. All refusals are 403 with a French reason (missing rights listed as `Domaine : Action`). The seeded ADMIN profile holds REGISTRE:CONSULTER + PARAMETRES + ADMINISTRATION only, so it cannot grant AGENT_TECHNIQUE, DGE or VETERINAIRE until the platform admin widens its matrix.
- **Domains** (`access/access-domains.ts`): programme REGISTRE, TECHNIQUE, INTRANTS, SANITAIRE, ECONOMIQUE, TRACABILITE, PILOTAGE, PARAMETRES, AUDIT, ADMINISTRATION; **Fermia-only** VENTES, MARCHE, COMPTABILITE, EQUIPE, CULTURES, COMPTE, PLATEFORME — refused by `validateMatrix`, so never reachable by an institution. Two domains sit outside any matrix and are open to every effective membership (the AUDIT scope included): `SESSION` (the caller himself, `GET /programme/access/me`) and `REFERENCE` (reference data for display: `GET /programme/provinces` with their localités — the only localités read — and `GET /programme/lists/:listType` active items; `?all=true` stays PLATFORM_ADMIN, and writes on provinces/localités/lists stay ADMINISTRATION). `GET /programme/provinces` is also open to Market buyers (public geography), the lists are not. A route may override its controller's domain (`@Domain` on the method); `@Action` when the verb is wrong (GET=CONSULTER, POST=CREER, PATCH/PUT/DELETE=MODIFIER).
- **`ProgramAccessGuard`** (global, after JWT): no-op for other roles. INSTITUTION: no `@Domain` → 403 (default deny), no effective membership → 403, matrix lacks the action → 403, AUDIT scope → `/audit` only, and any `:farmId` param must be in scope (unknown id = 403). RolesGuard then lets INSTITUTION through any route open to PROPRIETAIRE/ELEVEUR/PLATFORM_ADMIN (not buyer-only ones).
- **Scope** = `ScopeResolver` only (cached per request): `assertAccessible`, `resolveEffectivePermissions` (the farm codes mapped by `permission-domains.ts`, never `'ALL'`), `profileOf`, `findMine` and `/programme/farms` use it; `applyFarmScope(qb, alias, access)` is the SQL filter for any multi-farm list (never filter client-side). Only farms of the member's programme are ever in scope. PROVINCES = its provinces, FARMS = listed farms, FINANCED = **nothing until the BCEG consent model exists**, AGGREGATE/AUDIT/OPERATOR = no farm row.
- **Sanitary declarations** (`HealthEvent` today) = the farm + VETERINAIRE profile only, in the service (`SanitaryDeclarationPolicy`), whatever the matrix: the L5 surveillance module must call it too.
- **Login**: `INSTITUTION_OTP=off` (default, no SMS provider live) = login code only; `sms` = `POST /auth/login` answers `{ otpRequired, challengeId }` and sends a 6-digit code (`login_challenges`: bcrypt hash, 5 min, 5 attempts, 5 codes / 15 min → 429), then `POST /auth/login/otp` gives the token (`mfa: true`; JwtStrategy refuses institutional tokens without it while `sms`). Session 8 h either way. `SMS_PROVIDER=console` (logs, keeps the last messages for tests); `airtel`/`moov` are reserved and refuse to boot. `POST /admin/users/:userId/login-code` (PLATFORM_ADMIN) regenerates an 8-digit code for any non-admin account, returned once (`common/utils/login-code.ts` `newLoginCode`, shared with owner activation, membership creation and the two programme routes below); the previous code stops working, open sessions stay valid until they expire; there is **no forced change at first login** (no self-service code change exists). Without the platform admin: `POST /programme/farms/:farmId/owner-login-code` (ADMINISTRATION:ADMINISTRER, farm in scope; 409 `{ noOwnerAccount: true }` before `activate-owner`; never the caller's own; an institutional caller needs **every** farm of that owner in its scope, since the code opens them all) answers `{ farm, owner, loginCode }`, and `POST /programme/access/memberships/:id/login-code` (same rights as the membership routes, only for an account the caller could grant, never its own) answers the membership view plus `loginCode`. Both are journaled like any POST (the code never is).

### Bandes POUFA (L3, `modules/bandes`, core in `batches/poufa/`)
- **Every lot is a band** (every farm is a programme farm): `POST batches` opens it through `BandeOpeningService` (number, J+x, projection) and every daily entry goes through the offline conflict rules.
- **Code** `G1-0012-B07` (farm code + `IdCounter` scope `BANDE:<farmCode>`) set at opening, immutable (trigger `production_batches_code_immutable`). **J+x**: `integrationDate` = opening date, `initialAgeDays` offsets the age — **everywhere**: age = `initialAgeDays` + days since `integrationDate` (`bande-rules.ts` `ageOn`; J0 = `ageZeroDay`), used by the lot metrics (`ageDays`, breed-curve week, sale-age advice), the dashboard health rows, the cohabitation gap, care calendars (a step at age N is planned on J0 + N; ages already passed are skipped) and the Market ready date. GMQ / IPE (`flock-performance.ts` `growthOrigin`): growth counts from the weight measured at opening (`initialAvgWeightG`) when there is one, else from the chick weight at J0; IPE uses the true age. Lots placed as chicks (`initialAgeDays` 0/null, every pre-POUFA lot) are unchanged. A « lot en cours » entered with a back-dated `integrationDate` and no `initialAgeDays` is counted once; `referenceDurationDays` copied from `BANDE_DUREE_REFERENCE_J` at opening. A daily entry recorded after the day following its date is `catchUp`.
- **Sorties** (`sorties`, reason = RefItem `MOTIF_SORTIE`, family drives the flow): VENTE → Sale booked in the same transaction (`sales.create(…, {em})`), ABATTOIR → DRAFT slaughter order (birds leave at PROCESSED), REFORME/AUTRE → counted directly in `FlockReconciliationService` (`RETRAIT_FAMILIES`). Never count a VENTE/ABATTOIR sortie itself (double count). L7 hook: `SORTIE_CESSION_HOOK`.
- **Projection** `bande_daily_stats` (not journaled, derived): `BandeStatsService.refresh(em, batchId)` in the **same transaction** as every write touching headcount, feed, weight (daily entries, sales/cancel, orders fulfil, slaughter process, health events, sorties); it also **auto-closes** at 0 alive (`closureKind='AUTO'`, BATCH_CLOSED after commit). `POST …/daily-stats/rebuild` rebuilds. Hourly sweep (stale projections + late weighings, `WEIGHING_SWEEP_DISABLED=true` in e2e).
- **Snapshots** `bande_snapshots`: v1 at closure (bus listener, ensured by `GET …/snapshots`), immutable (trigger). A closed band changes only via `POST …/corrections` (PLATFORM_ADMIN, or a profile granted TECHNIQUE + ADMINISTRER from the administration — no default profile has it; reason ≥ 5 chars) → journaled + new version.
- **Indicators**: `FORMULE_*` parameters in force at the fact's date (end of day), division by zero → null; side effects (`runAfterCommit`) go after commit.
- **Offline conflicts**: rule in `backend/docs/poufa-conflits-hors-ligne.md` (French, for the CGI) — keep it in step with `sync/conflict-rules.ts`.

### Audit journal (`modules/audit`, POUFA/ANINF, `docs/audit-deploiement.md`)
- **Request context**: `common/context/request-context.ts` (`AsyncLocalStorage`), opened by `RequestContextMiddleware` (applied by `AuditModule` on every route): `requestId` = incoming `X-Request-Id` if it is a UUID, else a new one, echoed in the response (CORS exposes it). `JwtStrategy.validate` attaches the actor.
- **Level 1 (actions)**: global `AuditInterceptor` writes one `AuditEvent` per `POST/PUT/PATCH/DELETE` (success *and* failure, with status), per route marked `@AuditRead('reason')` and per `@AuditExport()` (`common/decorators/audit.decorator.ts`), and `POST /auth/login` as `LOGIN`/`LOGIN_FAILED` (phone masked, never the code). Requests refused before interceptors (guards: 401/403/429, 404, bad JSON) are journaled by `AuditExceptionFilter` from the plan `AuditPlanGuard` stored on the request — **`AuditModule` must stay imported before `AuthModule`** (global guards run in module order). The insert is awaited before the response, but `AuditService.record` never throws (`Logger.error`). Summary = body without keys matching `/pass|code|secret|token|hash|otp/i`, strings ≤ 500, ~8 KB. **Any new file route must return a `StreamableFile` with `@Res({ passthrough: true })` and carry `@AuditExport`** (a plain `res.send` answers before the journal is written); mark personal/HR/platform-wide reads with `@AuditRead`.
- **Level 2 (rows)**: PostgreSQL trigger `audit_row_change()` writes before/after into `audit_row_changes`, skipping UPDATEs that change only `updated_at`/`updatedAt`; `users.passwordHash` is never stored (`_redacted_changed` says it changed). Journaled tables: the 14 of `AuditJournal` plus the programme tables (`AuditProgrammeTables`: programs, provinces, localites, ref_items, program_parameters; not `id_counters`). **Every new business table gets `SELECT audit_attach('table')` in its migration.** `AuditContextSubscriber.afterTransactionStart` sets `app.request_id`/`app.actor_id` (`set_config(..., true)`), which covers `manager.transaction` and `repository.save/remove`; **query-builder and `repository.update/insert/delete` run without a transaction → null `request_id`** (level 1 still has the request). A new key table gets `SELECT audit_attach('table')` (or `audit_attach('t', 'key_col', ARRAY['secret_col'])`) in its migration.
- **Immutability**: triggers refuse UPDATE/DELETE/TRUNCATE on the three audit tables (French message). Don't write tests or seeds that delete journal rows; no FK from the journal to business tables.
- **Daily seal**: `AuditSealService.sealPendingDays()` (boot + hourly `setInterval`, `AUDIT_SEAL_DISABLED=true` in `test/e2e-setup.ts`) seals each UTC day 15 min after it ends: SHA-256 over prevHash + the day's rows, canonical (`audit-canonical.ts`, documented for ANINF). `verify(from?, to?)` reports the first COUNT/HASH/CHAIN/GAP mismatch. Routes `/audit/events[/export]`, `/audit/row-changes`, `/audit/seals`, `POST /audit/seals/verify` are `PLATFORM_ADMIN` + the ANINF profile (AUDIT scope) and journal their own reads.

### Feed stock / finance
- **FEFO auto-assignment**, stock never negative. Quantity by `entryType`: `BULKER`/`MATIERE_PREMIERE` = `tonnageMt×1000` kg; `BAG` = `nBags×bagSizeKg`; `MEDICAMENT` excluded from kg autonomy.
- Feed autonomy thresholds are **seeded reference constants**, not hardcoded: `FEED_STOCK_CRITICAL_DAYS`=3 (RED), `FEED_STOCK_WARN_DAYS`=5 (YELLOW), `FEED_ORDER_TARGET_DAYS`=7. Read them via `constants.get(...)`. Change the seed, not `feed-stock.service.ts`.
- **Cash only** (no Mobile Money). **Integer FCFA.** Caisse never negative. Lot creation (`chickUnitPriceFcfa`) and input receptions **auto-create expenses** (6010/6011 ↔ 401); `Expense.inputLotId` links reception expenses to their lot. The batch P&L counts those costs **once**: it adds `enrichment.chickCostFcfa`/`feedLotsCostFcfa` only when no matching expense exists (legacy data). Do **not** re-enter them as manual expenses. `inputValueFcfa` = unit price × (`numberOfBags` ?? `quantity`). Sale cancellation needs pessimistic locks + an open caisse + sufficient balance. Customers are find-or-create by phone (non-blocking). Promotion codes are uppercased and unique per farm (409 on duplicate).
- **Cash session opening** posts only the change from the previous session's declared closing (`AccountingService.cashOpeningLines`: more = apport 571/108, less = retrait 108/571), never the whole float. `recordPayment` locks the open session `FOR UPDATE` like `close()`. Egg stock is derived, so every egg availability check (POS sale, order create/fulfil, transfer) first takes `lockFarmEggStock()` (per-farm advisory lock).
- Customer balances (`customers.service.ts`) ignore sales wrapped by an order not yet delivered, and cap what is paid per sale at its total (a refunded over-deposit stays CONFIRMED). `POST /sales/:id/payments` refuses an undelivered order's sale (deposit via the order). Rentabilité and the platform `/admin` revenue count an order's revenue on its delivery date (`livred_at`), like the ledger; `initialize` skips undelivered orders, reception expenses (`inputLotId` / `[Auto] Intrant`, already booked as `input:`) and only reverses cancelled sales whose `sale:` entry exists.
- Sale types: `POULET_PIECE` requires integer qty; `PROVENDE` requires `inputLotId` (HACCP); `POULET_KG` requires `pieceCount` and decrements `quantityAlive`.

### Market listings
- A listing is `NOW` (birds or eggs, on sale) or `PRE` (birds only, with a future `readyDate` and an optional deposit %). `DRAFT→PUBLISHED⇄PAUSED→CLOSED`. Only `market:publier` writes them.
- Publishing needs a verified, active farm. **Visibility is evaluated at read time** (`listing-rules.ts`): a published listing leaves the catalogue when the farm is suspended or unverified, the lot ended, a sanitary hold applies, the ready date passed or no stock is free. Farm screens get the reason (`hiddenReason`). A `PRE` listing is only held back by a withdrawal period that reaches its ready date; overdue care can be caught up by then.
- Displayed quantity is capped by the free stock (`OrdersService.freeBirds`/`freeEggAlveoles`), as POS sales and mortality can lower it after publishing.

- **A `MarketOrder` is a request, not an order**: it touches no stock. Accepting (`vente:commande`) creates the real `Order` in one transaction (lock the request, then the listing, then `createWithin`), and from then on the farm works in its normal order screens. Price, fee and deposit are snapshotted server-side at request time.
- **Buyer status is derived at read time** (`market-order-rules.ts`) from the request and its `Order`, never stored twice; buyers get a whitelisted view with no `cancelledReason`. Remaining quantity = `quantityPublished` − accepted orders not cancelled; requests never count.
- **Deposit deadline**: a deposit % gives `depositDueAt` = acceptance + 24 h, and the farm can extend once. Unanswered requests expire after 48 h. `MarketSweepService.sweep()` runs at boot and hourly (`MARKET_SWEEP_DISABLED=true` in e2e) and cancels through `cancelForBuyer`, so any recorded deposit, even partial, keeps the order.
- **Buyer cancelling** (`POST /market/orders/:id/cancel`): unpaid is immediate, through `cancelForBuyer`. With money recorded it only sets `cancelRequestedAt`: the birds stay reserved and the farm cancels from its order screen, which refunds. **Moving a date** (`POST .../listings/:id/move-date`) updates the listing and its open orders' `expectedDate` in one transaction; silence keeps the order.
- **Market carcasses** (`CARCASS`, per piece, `NOW` only, from one PROCESSED `ABATTU` slaughter order): unlike birds, they leave `carcassesAvailable` when the order is **created**, so cancelling restores them explicitly (`restoreOrderCarcasses`; `skipStockRestore` skips the sale's own restore) and delivery only moves the difference. `birdsOf` returns 0 for them, or they would also reserve and decrement live birds. Sanitary holds don't apply: slaughter already refused a lot on hold. A cancelled carcass goes back on sale with no expiry check: the listing shows `slaughteredAt`, and the farm remains responsible for freshness.
- Market customers match on `Customer.buyerUserId`, not on the phone, since phones aren't verified. A Market order is refused delivery during a withdrawal period; a farm's own orders stay advisory.

### Points of sale / stock-transfers
- POS `FERME` (default: live birds + slaughter) vs `BOUTIQUE` (external, sells **only** farm-transferred reserves). A FERME POS is never reclassifiable to BOUTIQUE; `stockTransferId` is rejected on non-BOUTIQUE POS.
- `POST /stock-transfers` **decrements the source at creation**: `ABATTU` → `carcassesAvailable` of a PROCESSED order; `PROVENDE` → `InputLot.quantity` (SAC/KG via `farm.defaultSacKg`, default 50); `OEUFS` → derived reservation only (nothing decremented; `EGGS_PER_ALVEOL = 30`, transfers store alvéoles).
- `TRANSFERRED → CANCELLED`; cancel re-integrates `quantity − quantitySold` to the source. Each BOUTIQUE sale decrements `quantitySold` under a pessimistic lock; cancelling it restores via `restoreStockTransfer` (on an already cancelled transfer the units go back to the source and `quantitySold` drops too, so the feed valuation doesn't count them twice). A POS that received transfers can't be deleted (400: deactivate it).

### Orders
- An `Order` wraps a `Sale`; creation does **not** decrement stock, `fulfil` does (Market carcass lines are the exception, see below). State: `PENDING→CONFIRMED→LIVRE|CANCELLED`; a deposit (→ CONFIRMED) is **optional** — `fulfil` accepts PENDING or CONFIRMED (paid on delivery via `dto.payment`, or on credit: the sale stays OUTSTANDING). Open orders of both states reserve their birds. Delivering more birds than the order reserved may only use free birds (not other open orders' reservations nor SENT slaughter orders). A suspended farm can't deliver. Cancel passes `skipStockRestore:true`.
- **Never cancel an order's wrapped sale directly** — only via `orders/:id/cancel`, which is idempotent. Egg fulfil must exclude the order's own sale (`excludeSaleId`). All egg lines of an order are checked together (total and per batch), and egg lines keep their `batchId`. Create/deposit/deliver accept `vente:commande` or `vente:creer`; a replayed deposit (same idempotency key) returns the order instead of a 400.
- Internal paths with no route, for the Market: `OrdersService.createWithin(em, user, farm, dto, extras)` creates an order in the caller's transaction (the caller authorizes, then calls `afterOrderChange` after commit); `extras` (`source`, `deliveryFeeFcfa`, `customerType`) never come from the API. A delivery fee is an `AUTRE` line with no batch, so delivery recomputes it into the total and it is not a lot's revenue. `cancelForBuyer` only cancels an unpaid order, checked under the order lock, and otherwise returns an outcome. A `PRECOMMANDE` with an address keeps its delivery fields; without one they are dropped.
- **Lock ordering matters**: `sales.create` pre-locks *all* lots (sorted, deterministic) before POS items. Otherwise ABATTU→POULET inverts the graph relative to `slaughter.process` (lot→order) and deadlocks.

### Slaughter / sanitary
- `DRAFT→SENT→PROCESSED|CANCELLED` (terminal states immutable). `update`/`send`/`process`/`cancel` all re-read the order `FOR UPDATE` (send locks the batch first, like process); once SENT, `birdCount` and `slaughterType` are frozen. `birdCount ≤ quantityAlive` checked at send **and** at process. Active RED `DELAI_ATTENTE`/`PROPHYLAXIE` blocks shipment. Carcass weight ≤ live weight.
- **All date comparisons in UTC.** REFORME/MORTALITE health events decrement `quantityAlive` immediately and re-run the batch advisory. MORTALITE events are deaths **not** typed in the daily entries: every mortality figure (metrics, dashboard, curve, health trends, viability) adds `FlockReconciliationService.deathEvents()` to the entry deaths — but live-count reconciliation already subtracts them via `netSanitaryRemovedBirds`, so never subtract them twice.
- **Sanitary holds** (`sanitary/sanitary-holds.ts`) feed slaughter send, the passport and `readyForSale`: the withdrawal period is read from `TreatmentRecord.withdrawalEndDate` (the DELAI_ATTENTE alert can be acknowledged or stale), and an overdue care counts from the events themselves (EN_RETARD, or PLANIFIE older than `PROPHYLAXIE_RETARD_WARN_DAYS`) as well as a red PROPHYLAXIE alert, even ACQUITTEE. A cancelled care can't be completed or rescheduled; calendar generation skips past steps and refuses closed lots, and reading a closed lot's calendar raises nothing. Cancelling a care that took medication out of stock gives it back once (`stockConsumedAt` cleared).
- **`quantityAlive`** is always rebuilt by `FlockReconciliationService.recomputeLiveCount` (entries, sales, slaughter, REFORME/MORTALITE events) — health events recompute it instead of adding/subtracting. `BatchesService` writes only the columns it changed (`persist()`), never a full `save()` of an unlocked batch (it would write back a stale `quantityAlive`). A batch is created with `quantityAlive = quantityAtStart`; `close()` is idempotent. A building with non-closed lots can't be deleted.
- Pre-loaded `vacc-*` programs are **species- and type-specific**; the server rejects mismatches (400). Never ship a POULET program onto a non-POULET lot.

### Advisory & alerts
- **Advisory only, never blocking** — including HACCP and sanitary. Emit a red alert + recommendation + trace; the farmer decides. Water is the #1 indicator (drop in water + rising mortality → combined `MALADIE` RED/YELLOW). A daily entry can't be in the future (tomorrow tolerated), before the lot's `integrationDate`, nor add more deaths than live birds; changing its feed phase or ending an external purchase re-links it to a stock lot. One daily entry per batch per date (upsert on `(batch, entryDate)`; only the fields sent are overwritten, so the mobile sends zeros when editing an existing entry).
- Alert lifecycle: `ACTIVE → RESOLUE` when risk clears; manual `ACKNOWLEDGE` → `ACQUITTEE`, re-raised if the risk persists. Periodic re-evaluations pass `raise(..., { keepAcknowledgedIfUnchanged: true })` so an acknowledged alert only comes back when its `context` changes (compared with sorted keys and the same level, so multi-key contexts survive the jsonb round-trip). VIDE_SANITAIRE, TRACABILITE and the PROPHYLAXIE alerts use it.
- **Overdue tasks** (`TACHE`): `TasksService.sweepOverdue()` runs at boot and hourly (plain `setInterval`, no `@nestjs/schedule`), plus on task mutations and on `GET /tasks`. `TASK_SWEEP_DISABLED=true` turns the timer off (set in `test/e2e-setup.ts`; tests call `sweepOverdue()` directly).
- **Server push** (`modules/push`, Expo Push API, no SDK dependency): phones register `POST /push/devices` (`DELETE /push/devices/:token` on sign-out / toggle-off; a token belongs to one user, re-registering moves it). Triggers go through `koukouBus`, never direct calls: `ALERT_RAISED` (a **new** red alert or an escalation to ROUGE — re-evaluations of an existing red alert stay silent) → owner + active `ADMIN` staff; `TASK_ASSIGNED` (not self-assignment) → assignee; `TASKS_OVERDUE` → assignee (managers for unassigned or suspended assignees; a suspended member can't be assigned), once per task via `FarmTask.overdueNotifiedAt` (atomic claim, cleared when the due date moves; >7 days late = marked silently). Sends are fire-and-forget (`PushService.track`); `DeviceNotRegistered` tickets delete the token. `PUSH_DISABLED=true` in e2e; `push.e2e-spec.ts` swaps `PushService.deliver` and awaits `flush()`.
- **Batch indicators** (`batches/flock-performance.ts`, pure + unit-tested) are shared by `MetricsService`, the water alerts in `AdvisoryEngine` and the batch curve. Population on a day = start − daily-entry deaths − removals (`FlockReconciliationService.removalsByDate`: sales, slaughter, REFORME/MORTALITE events). FCR/GMQ/IPE are computed **at the last weighing** (feed and age up to that day); FCR divides by the biomass of every bird fed (present + sold/slaughtered/culled/dead at their interpolated weight). `waterLPerBird` = average L/oiseau/j over the last 7 days. Breed weight/FCR targets are taken at the weighing week. The IPE alert compares `ipe` with `ipeTarget` (breed curve at the weighing age, lot's own viability) — CHAIR lots with a standard only; never an absolute threshold.
- **Closed lots** (`CLOTURE`): `close()` stamps `ProductionBatch.closedAt`; `AdvisoryEngine.runForBatch` then only resolves the lot's batch-scoped alerts (`AlertsService.resolveClosedBatch`, keeping `CLOSED_BATCH_KEPT_KINDS` = TRACABILITE/RENTABILITE/VENTE) and re-evaluates traceability + its building. **Vide sanitaire** = days between the previous lot's end (`closedAt`, legacy fallback `updatedAt`) and the next lot's `integrationDate` in the same building, judged at placement (lot placed before the previous one ended = 0 days): < `VIDE_SANITAIRE_MIN_DAYS` ROUGE, < `VIDE_SANITAIRE_MAX_DAYS` JAUNE, else nothing. An emptied building raises nothing. Building-scoped alerts store `batchId` null (the lot is in `context.batchId`). `DatabaseSeedService.repairClosedBatchAlerts()` (boot, idempotent) pins `closed_at` and resolves alerts left by the old rule. Building `stats.lastLotEndedAt` feeds the mobile lot-creation hint (`mobile/src/utils/videSanitaire.ts`, same 14/21 defaults); `Building.lastVideSanitaireAt` is a manual field no rule reads.
- **Readiness is computed on read** in `MetricsService.compute()` (`readyForSale`/`readyReason`) and cached onto `ProductionBatch.readyForSaleAt` by `batches.service.afterChange`. `BatchStatus.EN_VENTE` is only a manual escape hatch.

### SYSCOHADA accounting
- Integer FCFA; entries **always balance**; posted **in the same transaction** as the business mutation. Idempotent via unique `(farmId, source, sourceId)` (tolerate PG `23505`). No TVA.
- Order revenue is recognized **at delivery**, not creation (the order-wrapper sale is written with a direct `saleRepo.save`). Cancelling before delivery posts only `cancel-deposits:`.
- Feed stock (Classe 3) → `311` (asset) ↔ `603`, valued per lot by available vs received kg.
- Accounts auto-seed via `ensureAccounts`; `Account.code` is unique per farm (class-level composite index).
- **Bilan = snapshot at `to`** (default today; `from` ignored): cumulative balances, classes 2–3 always actif, classes 1 (debts)/4/5 classified by balance sign, class 8 excluded. Capitaux = apports + **computed report à nouveau** (classes 6/7 before the exercice start + net `12`/`129`/`13`) + résultat of the exercice containing `to`. Balances by construction (`ecartFcfa` = 0). Until the exercice is closed, the feed stock on hand at `to` (`valeurStockProvende(asOf)`, same rule as the closing) is added to actif `311` and to the result as `variationStockFcfa`; the closing itself values the stock at the exercice end date. Manual régularisations dated in a CLOSED exercice → 400; automatic postings are still accepted (never blocking).
- Mobile write paths — `comptabilite.tsx`, `depenses.tsx`, `components/pos/CaisseTab.tsx` — are gated by `compta:rapports`/`compta:ecritures`/`compta:depense`. Non-manual cash movements (`SALE_PAYMENT`/`REFUND`/`EXPENSE`) are immutable.

- **Lists and details**: lists use `DataTable` (`components/ui.tsx`): header kept in view on a computer, stacked rows on a phone, so give every `Td` its `label` except the first, which acts as the row's title. Rules on `.data-table td` in `index.css` are unlayered and beat utilities, so hide a cell on a phone with `row-chevron` or leave it empty, not `max-md:hidden`. Between `md` and `xl`, hide secondary columns (`md:max-lg:hidden` on the `Td`, `hidden lg:table-cell` on the `Th`) rather than scroll sideways. Details open with `Modal side`; its slide-in has no fill mode because a lasting transform would trap the dialogs opened from inside it. Escape closes only the dialog on top. A long form uses `Modal large` with `FormColumns` (`components/form.tsx`): two columns from `lg`, one column in the same order below. Inside a `DataTable`, status pills stay on one line, but a long one wraps (class `pill-wrap`; the flock `Pill` adds it past 16 characters), because real data can be much longer than the demo's: a table that fits today can be cut tomorrow. ### Offline sync (`mobile/src/offline/`)
- Custom FIFO engine, zero dependencies (`engine.ts`/`storage.ts`/`store.ts`). Network failure (`TypeError` or `ApiError ≥ 500`) → enqueue. Every `*Queued` call goes through `sendOrQueue`: while the user's older ops for that farm are pending, the new op queues behind them (never overtakes live). On replay a refused (4xx) **creation** goes to the rejected list; a refused state transition (deliver/cancel/update/delete) is dropped. After `MAX_SERVER_ATTEMPTS` (10) consecutive 5xx a cash op is passed over (kept), any other op is rejected. Op ids are `off-<kind>-<time>-<random hex>` (unique across phones); each op stores its `userId` and is never replayed under another account. A queue read error throws (never overwrite what couldn't be read); a corrupt payload is copied to `koukou.offline.queue.corrupt.<ts>`. Every queued **creation** (sale, order, payments, feed input, feed loss, point of sale, stock transfer) sends `idempotencyKey = op.id` on the live attempt *and* on replay; the server returns the existing row via `createOnce()` (`backend/src/common/utils/idempotency.ts`, unique `(farmId, idempotencyKey)`). Daily entries are an upsert on `(batch, entryDate)`; state transitions (deliver/cancel/delete) answer a replay with 4xx, which drops the op harmlessly.
- `flushQueue()` returns `{synced, dropped, remaining}` and is guarded by a **mutex** promise so concurrent callers share one pass (no double-POST). `runFlush()` **re-loops up to 20 rounds** (`engine.ts`) while new ops arrive — never snapshot the queue.
- **Cash ops (`sale`, `order-payment`, `customer-payment`) must never be dropped.** `ensureCashOpen` opens a missing session with the last declared closing (`GET /caisse/sessions`), never 0. On replay it never reopens a caisse closed *after* the op's `createdAt` (evening close): the op stays queued (`skip`), flagged `heldByClosedCaisse` for `HeldCashNotice` (menu + caisse tab), and goes out once a session is open; cash recorded after the close still auto-opens, like the live path. `ensureCashOpenOrRetry()` deliberately rethrows a plain `Error` (not `ApiError`) so a 4xx from the caisse step maps to *retry*, not *drop*.
- `OfflineAutoSync` (mounted in `_layout.tsx`) flushes on reconnect/pending-op, ref-guarded. Invalidate via `invalidateFarmQueries()`.

### Reference data per farm
- `Breed`, `Culture` and `SanitaryProtocol` carry a nullable `farmId`: **null = shared, seeded reference data**; custom rows belong to the farm that created them. A farm sees and uses shared rows + its own (`common/utils/farm-scope.ts` `sharedOrFarm()`); names/codes are unique among shared rows and within a farm (partial + composite unique indexes, class-level). `GET /breeds|/cultures|/sanitary/protocols[/:id]` take `?farmId=` (without it: shared only); `POST` needs `farmId` in the body (`FarmsService.resourceScope`; only PLATFORM_ADMIN may create a shared row). Batch creation (`breedId`), parcelles (`cultureId`) and program generation (`protocolId`) refuse another farm's row. Seed lookups filter `farmId IS NULL`. `DatabaseSeedService.assignLegacyCustomResources()` (boot, idempotent) gives each legacy custom row used by exactly one farm to that farm — except protocols a PLATFORM_ADMIN created as shared (`SanitaryProtocol.adminShared`). The seed matches breeds and breed standards by `refCode` first (a renamed seed row is updated, not duplicated) and writes each protocol with its steps in one transaction.

## OpenCode (native subagents)

Config: `opencode.json` (root). Subagents run in child sessions and inherit parent context — keep prompts tight.

- **Flow**: prefer Plan for analysis, switch to Build only when ready to edit.
- **Available subagents here are `@explore` and `@general` only** (no `scout`, despite the stale `"scout": "allow"` entry in `opencode.json`). `@explore` is read-only and cheapest — use it for grep/glob/file discovery. `@general` has full tools including edits. - **Context hygiene**: spawn from a clean turn; don't fan out from a very long session.
